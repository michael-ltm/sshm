# 本地私钥与 AI 免输入连接检查

检查范围：四台设备当前 SSHM 配置引用的密钥；按每台设备上的文件路径去重，跨设备副本分别计数。只输出加密标志、文件存在性、权限及 Agent 公钥匹配结果，未输出或读取 `.passphrase` 内容。未遍历未被配置引用的其他私钥、备份或密码管理器。

| 设备 | 引用的私钥文件 | 已加密 | 未加密 | 旁边有 .passphrase |
| --- | ---: | ---: | ---: | ---: |
| 本机 Mac | 20 | 17 | 3 | 7 |
| Mac mini | 7 | 7 | 0 | 3 |
| GrokBot | 8 | 8 | 0 | 0 |
| att-dev | 24 | 12 | 12 | 16 |
| 合计 | 59 | 44 | 15 | 26 |

“旁边有口令文件”与“已加密/未加密”不是互斥分类。口令文件是否仍匹配私钥未验证，不能将所有文件视作当前有效凭据。

本机三份未加密私钥分别用于 jinqun、yann、ttbee-new。Windows 有十二份未加密文件，包含部分从其他设备迁入的副本；没有为了本次检查更改其内容。

macOS/Linux 被检查的私钥及现有口令文件权限均为 0600。Windows 检查了 40 个私钥及旁边的口令文件，未发现向当前用户、SYSTEM、Administrators 之外的主体授予 Allow 权限。文件权限不能保护被复制后的未加密私钥，也不隔离已获得本机用户权限的程序。

本机 Agent 持有全部 17 份加密私钥对应的公钥身份。Windows Agent 可用，但并非所有加密私钥都已加载。Mac mini 和 GrokBot 的被检查远程 SSH 会话没有可用 Agent；这不能直接代表它们的其他桌面或 AI 会话状态。

当前桌面内置 MCP 的旧进程缺少 SSH_AUTH_SOCK，真实调用失败。继承系统 Agent 的临时 MCP 真实连接 Mac mini、GrokBot、att-dev 全部成功且没有密码输入。

已实现 macOS 在环境变量缺失时从当前用户 launchd 查找 Agent，仅接受当前用户拥有的 socket，不读取恢复文件、不自动解锁、不扫描其他用户 Agent。新版 MCP 刻意清空 SSH_AUTH_SOCK 后，仍完成上述三个真实 SSH 执行检查。

修复已随 `0.8.0-cloud-preview.5` 签名发布并安装到四台设备。已有 MCP 长驻进程需重新连接或重启后加载新版。本地更新时并发 SSH 检查改变了活动时间，导致全结构即时比较失败；随后旧/新二进制读取同一配置完全一致，且与之前扫描的路由、密钥引用、公钥指纹和业务元数据逐项一致。三台远端更新前后完整列表一致。

额外签名预检中，本机 20 份私钥有 19 份通过公私钥配对与实际签名检查；`xm-prod` 缺少旁边的 `.pub` 文件，因此该项预检未完成。对它的实际 SSH 检查收到 `ssh: handshake failed: EOF`，不能据此确认当前可连接。未修改该服务器或密钥。

本次没有删除恢复文件、重写私钥或更换服务器 authorized_keys。后续加固需要先确认每份密钥的持久解锁/恢复来源，再逐份加密旧私钥并验证相同公钥的登录可用性，最后处理明文恢复副本。仅凭当前 Agent 能签名不足以证明重启后可恢复。
