# Preview.36：同步修复与残留清理

日期：2026-09-28。官网和六平台签名下载已发布 `0.8.0-cloud-preview.36`。四台客户端文件均已更新；本机 Linux 与 MacBook Air 的本地服务已恢复并验证。Mac mini 和 GrokBot 的旧云代理仍保留，迁移所需的两项敏感操作等待明确授权，不能计为全部完成。

## 已修复的原因

- 云端同一目标可能包含多台设备的不同 SSH 密钥。旧导入把所有密钥写入显式 `KeyPath` 的本机绑定，后续身份检查因此失败。现在只导入匹配当前真实私钥文件公钥的凭据；缺文件时保留已有本机凭据并跳过新导入。
- 旧 Agent 公钥缓存也会在本机文件不可用时选中其他设备的密钥。现在显式文件约束覆盖 v2 与旧缓存，旧缓存仅迁移匹配且能签名的密钥。
- 每轮导入合并为一个原子本机存储事务；38 个目标的回归测试从 40 次保护器打开降为 1 次。完整验证、显式锁、禁用状态、失败与取消回滚仍保留。实机同步失败由身份选择污染确认，不能归因于未经实测的超时。
- 兼容旧版 `systemd-creds`，去掉其不支持的 `--no-ask-password` 参数，保留用户与凭据名称绑定及系统主机密钥保护。
- `cloud status` 遇到损坏或不可读状态会返回错误，不再一律显示未配置账号。
- 官网使用“客户端版本”，将可选网页终端连接与本地 SSH 区分；没有实时代理时不把旧心跳当成当前进程，也不因未知版本要求重复重启或解锁。

## 加密备份与待授权操作

三台远端迁移前完整备份均已用一次性 X25519 封装和 AES-GCM 加密，并在本机仅于内存中解密遍历验证。私有归档和恢复说明位于 `dist/operational-recovery-20260928/`；接收私钥留在当前电脑系统保护的 SSHM 存储中，未打印或传输。这些归档依赖该受保护接收密钥，不能当作独立口令恢复包。

仍有两项待用户明确批准：

1. GrokBot：安装 root 管理的原生凭据服务，接口限定 `box` 用户 0600，并通过已有容器监督程序及登录注册启动。临时原生测试证明跨进程与服务重启可解密，其他用户与错误名称被拒绝；自动审批拒绝了持久安装，系统启动路径尚未改动。没有导出系统主机凭据密钥。
2. Mac mini：从当前已配对电脑向指定 Mac mini 发送仅该接收进程能解密的恢复 grant，保留原账号和 token。协议绑定账号、来源、根公钥、设备、请求、公钥、PID 和期限，已测试和独立审查；自动审批拒绝了敏感材料传输。没有上传 grant；接收任务已过期并清理，继续时必须创建新请求并使用最终源码重编 helper。

未终止正在使用的 AI/MCP 会话。旧会话需要重新加载客户端以使用 `.36`；不能把新安装版本当作旧进程已升级。没有实际重启整台机器；服务重启、GUI 新进程、CI 和真实 SSH 连接分别有上述证据。原有 legacy PEM 的独立 `.pub` 读取路径不在本次缓存修复范围。
