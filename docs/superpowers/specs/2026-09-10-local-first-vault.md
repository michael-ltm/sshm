# 本地优先 SSH 与加密云同步

用户已明确授权本次架构变更：恢复原先本地连接体验，取消默认逐 MCP 进程浏览器批准，保留云同步，并兼顾加密与防泄漏。此前延长 MCP 授权期限只是过渡，现改为默认本地模式。

## 行为

- 默认 MCP、CLI 使用本机私钥和同用户 SSH Agent。云端索引不再阻断本地已有身份。
- `sshm cloud agent` 在本机交互解锁一次，把 vault 中能解密、对应当前有效连接的身份载入本机 Agent；后续 CLI/AI 共用签名能力，无须逐进程批准。
- 密钥仍加密保存在 vault 中；不生成明文私钥、口令 sidecar 或主密钥缓存。密钥解析与加载发生在内存。已有 Agent 身份不被清空或替换。
- 保存仅含公钥的本地连接身份缓存，按完整连接路线及云条目标识匹配，不能使用别名通配符选择其他连接的身份。缓存路径由摘要产生，不能由别名构造任意路径。
- 每次 Agent 加载前验证私钥派生的实际公钥；加密私钥缺口令时明确报告无法加载，不声称 vault 解锁等于 SSH 私钥解锁。
- 缺少本地身份时，交互 CLI 可使用已有 vault 解锁流程；非交互 MCP 提示在本机运行 `sshm cloud agent`。
- 保留显式 `sshm mcp --cloud-auth browser` 作为需要逐进程浏览器批准时的可选模式，其 2 小时空闲／12 小时总期限策略不变。
- 主机密钥检查、日志脱敏、命令审计和显式破坏性命令保护继续有效。云同步的签名、加密、冲突及删除处理继续保留。

## 边界

本地模式下，云端撤销不等于立即撤销已经载入本机 Agent 的签名能力；本机 Agent 生命周期及密钥期限控制本地可用性。需要即时云端授权检查时使用 browser 模式。
同用户恶意程序能使用同用户已解锁 Agent，这与普通本地 SSH 的权限边界一致。磁盘及云端副本的加密不声称防御已被控制的登录会话。

此次架构修改不会恢复丢失的私钥口令。prod-go/prod-dev 仍需独立恢复已删除条目并验证原始密钥或其他获授权登录途径。

## 工作目录与验证

当前目录含大量用户已有未提交修改。采用文件职责分工，在原目录保留并扩展这些修改，不重置、覆盖整文件或提交无关更改。
以真实本地 SSH 测试服务与 Unix Agent 验证：默认 MCP 无浏览器请求即可执行；连接身份不串用；停止/过期后的行为清楚；browser 模式继续拒绝未批准访问；无秘密明文文件生成。Windows 和 macOS 至少编译检查。
