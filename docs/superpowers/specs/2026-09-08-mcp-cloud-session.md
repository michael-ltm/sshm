# Browser-approved MCP cloud sessions

The current MCP sees published cloud metadata but cannot authenticate. CLI link/watch keeps keys in a different process. Implement a process-owned MCP session reusing the existing signed ECDH link protocol. No local credential export or unauthenticated IPC broker.

MCP tools: cloud_unlock (reason required; no secrets or endpoint overrides), cloud_unlock_status, cloud_lock (reason required). Existing configured cloud account and pinned root are required. Begin returns only approval URL, verification code, expiry and state; polling runs in this MCP process. The browser labels the request as MCP credential access. Approval holds only the master key and ephemeral device token in process memory; do not replace the CLI account or persist that token. Lock/restart/15-minute idle/one-hour maximum invalidates access; best-effort revoke ephemeral device. Existing operations may finish; lock blocks subsequent connection admission. Verify remote authorization and signed vault contents on each new connection; no offline fallback. Discard session on revoked token, changed local account/root or invalid signature/rollback.

Dial resolves a cloud binding to its authenticated vault entry before using credentials. Match account/root plus entry ID and route; reject missing/conflicted/deleted entries, unsupported device terminals, external ProxyCommand/forward/SOCKS routes and nested jumps. Only vault-owned simple ProxyJump routes are supported. No local key or agent fallback for cloud credentials; missing/ambiguous password or encrypted key needs user correction outside chat. Preserve host-key verification, command filters, audit and redaction. Native servers are unchanged.

Read-only MCP must not gain new credential access. Full MCP advertises the approval tools. Each process owns a separate session; never accept secrets as tool inputs. Existing tool result wrappers remain in use; session status and audit entries use a closed set of non-secret fields. Credential memory clearing is best-effort in Go; do not claim protection against same-user process inspection or arbitrary authorized remote commands reading remote secrets.

Validation: synthetic browser approval using real crypto; wrong identity/root/signature and expiry rejection; no files containing plaintext/token, safe tool output/audit, multiple sessions isolated, cancellation/lock races, revoked grant fails before SSH, actual loopback SSH execution through cloud credentials. Run focused tests and race checks. Known baseline: Windows pair command length test fails at 8207 > 8190 bytes.
